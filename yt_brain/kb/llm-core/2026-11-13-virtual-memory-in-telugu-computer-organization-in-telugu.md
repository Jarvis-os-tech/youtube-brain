## Core Concept
Virtual memory is a memory management technique that creates the illusion of a very large main memory by combining limited physical RAM with secondary storage (disk/swap space), automatically moving only the needed parts of a program between them as execution proceeds.

## Key Takeaways
- Virtual memory is an illusion built on two components: physical main memory (RAM) and secondary storage (disk/swap space).
- The CPU generates a logical/virtual address, which the virtual address space splits into pages; these flow through the Memory Management Unit (MMU) to main memory, where they become frames.
- If the needed instruction/data is not in RAM, a page fault occurs and the OS fetches it from disk/swap space, swapping between RAM and secondary storage.
- The virtual address space generated by the CPU can be larger than physical RAM; the physical address space is the actual addresses in RAM.
- The MMU converts virtual addresses into physical addresses.
- Virtual memory is divided into fixed-size blocks called pages; physical memory is divided into same-sized blocks called frames.
- If too many page faults occur, the CPU spends more time swapping than executing — this condition is called thrashing and severely reduces performance.
- Advantages: programs larger than physical memory can run; protection between processes; efficient RAM use (only needed parts loaded).
- Disadvantages: secondary storage is much slower than RAM; page faults cause delay; requires extra hardware (MMU); excessive paging can lead to thrashing/crashing.
- Example given: a computer with 2GB RAM running a 6GB program — the OS loads some parts into RAM and stores the rest on disk, swapping required pages automatically as execution proceeds.

## Technical Details
- Terms: logical/virtual address, virtual address space, page, frame, page fault, MMU (Memory Management Unit), physical address space, swap space, thrashing, paging.
- Flow: CPU → virtual/logical address → virtual address space (pages) → MMU → main memory (frames); on miss → secondary storage (disk/swap space) → swap back to main memory.
- Swap space holds parts of programs and data not currently in use; the OS automatically moves data between RAM and secondary storage when needed.
- Paging divides virtual memory into fixed-size pages and physical memory into equal-sized frames.
- Thrashing: continuous swapping due to excessive page faults; performance reduced severely.
